# AI 值守员 产品需求文档

版本 v0.1 · 2026-11-13 · 状态：待评审

---

## 0. 一页摘要

**一句话定位**：给企业的每一路摄像头配一个 AI 值守员。企业用一句话告诉它“盯什么、发现了通知谁”，它 7×24 小时值守；值班人员随时可以用语音或钉钉对它下指令、问情况。

**核心设计**：产品围绕**岗位**和**职责**组织。每个摄像头是一个岗位，岗位上挂着一份职责清单。用户打开系统看到的第一屏就是这份清单：它在负责什么、现在是否在工作、今天发现了什么、发现后通知了谁。

**一期目标**：在一个行业场景里跑通“配置职责 → 自动发现 → 钉钉通知 → 有人处理 → 统计误报”的闭环，让客户愿意持续开着它。

---

## 1. 产品定位

### 1.1 要解决的问题

| 现状 | 问题 |
|---|---|
| 监控室靠人盯屏 | 人盯不过来，注意力 20 分钟后明显下降；夜班、多路画面更难 |
| 录像事后查 | 出了事才去翻录像，耗时，不能及时止损 |
| 传统视频 AI 算法 | 只能识别厂商预置的固定类别（安全帽、区域入侵等），新需求要定制训练，周期长、成本高 |
| 配置门槛高 | 规则要专业人员画线、调参数，业务人员改不了 |

### 1.2 我们的做法

- **用自然语言定义职责**：“有人吸烟就通知安全群”，不需要训练算法，当天提出当天生效。
- **能对话**：值班员可以直接问“门口现在有几个人”“上午 9 点左右发生了什么”，不用翻录像。
- **有记忆**：自动记录画面时间线，可以按时间回溯、出报告。
- **接入企业已有的协作工具**：通知和指令都在钉钉、飞书里完成，不需要额外装 App。

### 1.3 目标客户与场景

| 场景 | 典型职责 | 优先级 |
|---|---|---|
| 工厂车间 | 未戴安全帽、吸烟、明火烟雾、人员倒地、离岗、设备仪表巡检 | 建议首选 |
| 仓库物流 | 吸烟、通道堆物、叉车区闯入、夜间闯入、门未关 | 建议首选 |
| 机房、配电室 | 无人值守巡检、仪表读数、门禁异常、烟雾 | 次选 |
| 园区、写字楼 | 陌生人进入、夜间闯入、消防通道占用 | 次选 |
| 门店 | 店员离岗、顾客排队过长、闭店后有人 | 后续 |
| 工地 | 未戴安全帽、未穿反光衣、危险区域闯入 | 后续 |

建议一期**只做一个行业**（工厂车间或仓库），把模板、默认职责、话术都做深，再复制到其他行业。

### 1.4 产品形态

- **私有化部署**：一台 GPU 服务器（当前为 4×RTX 3090），放在客户内网，画面不出厂区。
- **接入**：RTSP 网络摄像头，或浏览器推流（演示、临时用）。
- **使用入口**：网页值守台（大屏、电脑）、钉钉、飞书；现场可接音箱做语音播报。

## 3. 核心概念

### 3.1 概念关系

```
岗位（一个摄像头点位）
 ├─ 岗位信息：名称、看哪里、场景说明、值守时间、负责人
 ├─ 职责清单
 │   ├─ 长期职责（管理员配置）── 盯守类 / 巡检类 / 汇报类
 │   └─ 临时任务（值班员下达，有有效期）
 ├─ 指令（随时问答，不形成职责）
 └─ 事件记录
     └─ 告警（职责命中产生）── 通知 → 处理 → 结果
```

### 3.2 岗位

一个摄像头就是一个岗位。岗位信息决定了 AI 理解画面的背景，也是用户认知的入口。

| 字段 | 示例 | 说明 |
|---|---|---|
| 岗位名称 | 1 号仓库门口 | 通知、报表里都用这个名字 |
| 看哪里 | 仓库大门和装卸区，左侧是叉车通道 | 帮助 AI 理解画面 |
| 场景说明 | 仓库内禁止吸烟、叉车通道禁止行人停留 | 规章、常识，所有职责共用 |
| 值守时间 | 全天 | 岗位级别的总开关 |
| 负责人 | 张三 | 紧急告警 @ 的人 |

### 3.3 职责（三类）

| 类型 | 说明 | 例子 | 运行方式 |
|---|---|---|---|
| **盯守类** | 发生了就通知 | 有人吸烟、未戴安全帽、离岗超过 10 分钟、陌生人进入、明火烟雾、人员倒地、通道堆物 | 后台持续看，命中且确认后通知 |
| **巡检类** | 到点检查并记录 | 每天 9:00、15:00 读压力表；每小时数一次在岗人数；下班后检查门是否关好 | 到点看一次，记录结果，异常才通知 |
| **汇报类** | 到点总结 | 每天 18:00 发当日值守报告；每周一发周报 | 到点基于记录生成报告并发送 |

“随时问答”是值守员的能力，不是职责。

### 3.4 一条职责的要素

| 要素 | 必填 | 示例 | 说明 |
|---|:-:|---|---|
| 名称 | ✓ | 禁止吸烟 | 一眼能懂 |
| 类型 | ✓ | 盯守类 | |
| 判定内容 | ✓ | 画面中有人吸烟或手持点燃的香烟 | 自然语言；系统会改写成 AI 更容易判断的描述并给用户确认 |
| 参考图 | | 算违规：2 张；不算：1 张（手拿笔） | 提高准确率，误报截图可一键加入“不算” |
| 检测区域 | | 仓库门口区域（画面框选） | 一期可不做，用文字描述代替 |
| 生效时间 | ✓ | 全天 / 工作日 8:00–18:00 | 默认继承岗位值守时间 |
| 命中条件 | | 持续 5 秒以上；或离岗超过 10 分钟 | 盯守类专用，用于“持续多久才算” |
| 级别 | ✓ | 一般 / 重要 / 紧急 | 决定通知方式和是否升级 |
| 通知对象 | ✓ | 钉钉“安全值班群” | 可多选：钉钉群、钉钉个人、飞书群、网页值守台 |
| 现场动作 | | 现场播报“仓库内禁止吸烟” | 需现场有音箱 |
| 防打扰 | ✓ | 同一事件 10 分钟内只通知一次 | 默认值按级别给 |
| 运行模式 | ✓ | 正式 / 试运行 | 试运行只记录不通知 |
| 来源 | 自动 | 模板“仓库安全” / 管理员李四 | 用于审计 |

### 3.5 临时任务

值班员用语音或钉钉临时下达的职责，例如“今天下午盯一下门口，有快递到了告诉我”。

- 默认**当天 24:00 到期**，也可以说“盯 2 个小时”。
- 默认通知给**下达任务的人**：在钉钉群里下达就发回这个群，在网页上下达就在网页上提醒并语音播报。
- 在岗位卡上和长期职责分开显示，标明谁下的、什么时候到期。
- 可以“转为长期职责”，需要管理员权限。

区分临时任务的目的：避免随口加的规则越积越多，让职责清单始终干净、可信。

### 3.6 告警

职责命中后产生一条告警，状态如下：

```
待确认（AI 二次确认中）──确认不成立──▶ 丢弃（只记日志）
   │
   ▼ 确认成立
已通知 ──有人点“收到”──▶ 处理中 ──▶ 已处理
   │                          └──▶ 误报
   └──超时未响应──▶ 升级通知（二期）
```

每条告警记录：岗位、职责、时间、截图（命中时、确认时）、AI 给出的依据、通知了谁、谁在什么时候处理、处理结果。

## 4. 功能需求

优先级：P0 一期必须；P1 一期尽量，可延后；P2 二期及以后。

### 4.1 岗位卡（首屏）

用户打开值守台，第一屏就是岗位卡。目标：**5 秒内看懂“它在负责什么、现在好不好、今天有没有事”。**

```
┌──────────────────────────────────────────────────────────────────────┐
│ 1号仓库门口   ● 值守中    今日告警 3 · 待处理 1 · 误报 0                    │
│ 看哪里：仓库大门和装卸区                                                  │
├──────────────────────────────────────────────────────────────────────┤
│ 我的职责                                                  [+ 添加职责] │
│ ● 禁止吸烟    盯守 全天            → 钉钉·安全群        今日 1 次  14:32   │
│ ● 离岗提醒    盯守 工作日 8-18 点    → 钉钉·班组群        今日 2 次  11:05   │
│ ○ 夜间闯入    盯守 22:00-06:00     → 钉钉·保安群+现场喊话  未到生效时间     │
│ ● 压力表巡检  巡检 每天 9:00 15:00   → 记录，超 0.6MPa 通知  9:00 0.42 正常 │
│ ● 每日报告    汇报 每天 18:00       → 钉钉·安全群        今天未到时间       │
│ ◐ 未戴安全帽  试运行中（第 1 天，命中 4 次，待你确认准不准）  [查看]         │
├──────────────────────────────────────────────────────────────────────┤
│ 临时任务                                                              │
│ ● 有快递到门口就告诉我    值班员张三 · 今天 18:00 到期        [转为长期]   │
├──────────────────────────────────────────────────────────────────────┤
│ 你可以这样问我：门口现在有几个人？上午 9 点左右发生了什么？有人吸烟就告诉我。   │
└──────────────────────────────────────────────────────────────────────┘
```

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-101 | 显示岗位名称、值守状态（值守中 / 摄像头离线 / 模型异常 / 已暂停）、今日告警数、待处理数 | P0 |
| F-102 | 列出全部长期职责：名称、类型、生效时间、通知对象、今日触发次数、最近一次时间或巡检结果 | P0 |
| F-103 | 每条职责显示运行状态：运行中 / 不在生效时间 / 已暂停 / 试运行 / 异常（如通知渠道未配置、发送失败），异常要说明原因 | P0 |
| F-104 | 单独列出临时任务：内容、下达人、到期时间 | P0 |
| F-105 | “添加职责”入口在岗位卡上常驻，没有职责时显示引导：“选择行业模板”或“用一句话描述” | P0 |
| F-106 | 点击职责展开：最近触发记录（时间、截图、依据、处理结果）、编辑、暂停、试一下 | P0 |
| F-107 | 显示“你可以这样问我”的示例，示例根据当前职责和场景生成 | P1 |
| F-108 | 状态实时更新（职责触发、新告警时无需刷新页面） | P0 |

### 4.2 职责管理

**添加职责的三种方式**

| 方式 | 适合谁 | 说明 | 优先级 |
|---|---|---|:-:|
| 行业模板 | 新客户、管理员 | 选行业，勾选要启用的职责，统一设置通知群，一次添加 | P0 |
| 一句话描述 | 管理员、值班员 | 输入“仓库里有人吸烟就发钉钉安全群，紧急”，系统拆成表单（名称、判定内容、通知对象、级别、生效时间），用户确认后保存 | P0 |
| 表单 | 管理员 | 逐项填写，适合精细调整 | P0 |

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-201 | 新增、编辑、暂停/启用、删除职责；删除需二次确认 | P0 |
| F-202 | 一句话描述自动拆成职责表单，用户确认后才生效；拆不出的必填项（如通知对象）要追问 | P0 |
| F-203 | 判定内容由系统改写为“可从画面直接判断”的描述并展示给用户，例如“离岗”改写为“工位座椅上没有人，持续 10 分钟” | P0 |
| F-204 | **试一下**：用当前画面立即检查一次，显示结论、依据和截图；可选发一条测试通知到对应群 | P0 |
| F-205 | **能力提示**：保存时根据判定内容给出提示，例如“吸烟属于小目标，距离 10 米以上时识别率下降，建议先试运行” | P1 |
| F-206 | **试运行模式**：只记录不通知；岗位卡显示试运行天数和命中次数，用户逐条标记准/不准后转为正式 | P1 |
| F-207 | 参考图：上传或从当前画面截取，标注“算”或“不算” | P1 |
| F-208 | 盯守类的持续条件（持续 N 秒/分钟才算命中） | P1 |
| F-209 | 巡检类职责：定时检查、记录结果、超出阈值时通知 | P1 |
| F-210 | 汇报类职责：定时生成报告，发到指定群 | P0（已有定时报告能力，改为职责形式） |
| F-211 | 检测区域框选 | P2 |
| F-212 | 职责变更记录：谁在什么时候改了什么 | P1 |

### 4.3 指令交互

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-301 | 支持语音（网页、现场麦克风）、文字、钉钉、飞书下指令；回答简短，一句话结论 | P0（已有） |
| F-302 | 问“你负责什么”“你现在在盯什么”，按岗位卡回答，例如“我负责 4 项：禁止吸烟、离岗提醒、夜间闯入、压力表巡检，还有 1 个临时任务。” | P0 |
| F-303 | 语音下达“……就提醒我 / 就通知……”时生成**临时任务**，并**复述确认**：“已添加临时任务：有人吸烟时通知安全群，今天有效。” | P0 |
| F-304 | 语音下达的内容不明确时追问一次，如“通知到哪个群？” | P1 |
| F-305 | 语音暂停、恢复、取消职责：“暂停离岗提醒”“取消刚才的任务”；涉及长期职责需要管理员权限 | P1 |
| F-306 | 问职责相关的历史：“今天有几次有人吸烟”“最近一次离岗是什么时候”，按告警记录回答并附截图 | P0 |
| F-307 | 超出能力范围的问题明确拒答，不编造 | P0（已有） |

### 4.4 告警通知

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-401 | 每条职责独立设置通知对象：钉钉群、钉钉个人、飞书群、网页值守台；可多选 | P0 |
| F-402 | **二次确认**：初次命中后放大可疑区域、隔几秒再看一次，两次都成立才通知；默认开启，单条职责可关闭 | P0 |
| F-403 | 通知内容：岗位名称、职责名称、时间、AI 依据、截图、“查看现场”链接、处理按钮 | P0 |
| F-404 | 级别：一般（只发群）、重要（发群并在网页上弹窗）、紧急（发群并 @ 岗位负责人，同时现场播报） | P0 |
| F-405 | 防打扰：同一职责冷却时间内只通知一次；冷却期内再次命中合并计数，下次通知时注明“期间又发生 3 次” | P0 |
| F-406 | 现场语音播报（如“仓库内禁止吸烟”），需现场有音箱 | P1 |
| F-407 | 没有配置通知对象，或发送失败时，在岗位卡上标红并说明原因 | P0 |
| F-408 | 通知渠道可扩展：企业微信、短信、电话、声光报警器 | P2 |

### 4.5 告警处理闭环

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-501 | 告警列表：按岗位、职责、时间、状态筛选；查看截图和依据 | P0 |
| F-502 | 处理状态：待处理 → 处理中 → 已处理 / 误报；记录处理人、时间、备注 | P0 |

| F-505 | 超时升级：重要/紧急告警 N 分钟无人响应，@ 负责人或发给上级 | P2 |

### 4.6 行业模板

| 编号 | 需求 | 优先级 |
|---|---|:-:|
| F-601 | 内置首个行业的模板（建议工厂车间或仓库），含 6～10 条常用职责，判定内容和默认参数都调好 | P0 |

## 5. 关键流程

### 5.1 首次开通（目标：30 分钟内收到第一条有效告警）

1. 管理员打开值守台，填写岗位信息（名称、看哪里）。
2. 选择行业模板，勾选要启用的职责。
3. 配置钉钉：填写应用凭证，把机器人拉进群，一键设为通知群。
4. 每条职责点“试一下”，确认 AI 看得懂这个画面。
5. 不确定准不准的职责设为试运行，其余直接正式开启。
6. 岗位卡显示“值守中”，开通完成。

### 5.2 管理员添加一条职责

1. 在岗位卡点“添加职责”，输入“仓库里有人吸烟就发钉钉安全群，紧急”。
2. 系统生成表单：名称“禁止吸烟”、判定内容“画面中有人吸烟或手持点燃的香烟”、级别紧急、通知“钉钉·安全群”、全天、冷却 10 分钟，并提示“小目标，建议先试运行”。
3. 管理员调整后点“试一下”，看到结论和截图。
4. 选择“正式开启”或“试运行”，保存后岗位卡立即出现这条职责。

### 5.3 值班员语音下达临时任务

1. 值班员说：“今天下午有快递到门口就告诉我。”
2. 系统复述：“已添加临时任务：有快递员或快递车到门口时提醒，今天 18:00 前有效。”
3. 岗位卡“临时任务”区出现该任务。
4. 命中后在网页上提醒并语音播报；到期自动结束。

### 5.4 告警处理

1. AI 初次命中“禁止吸烟”，放大确认后成立。
2. 钉钉安全群收到卡片：岗位、职责、时间、截图、依据、“查看现场”和处理按钮。
3. 安全员点“收到”，状态变为处理中；到现场处理后点“已处理”，或判断不是吸烟后点“误报”。
4. 误报时可选择把截图加入“不算”参考图。
5. 当天报告里汇总这条告警及处理结果。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **准确率** | 每条模板职责在目标场景下的确认后准确率 ≥ 85%，误报率 ≤ 15%（以试运行标注数据统计）；达不到的职责在模板中标注为“需试运行” |
| **预期管理** | 页面上明确告诉客户能力边界：检查间隔约 5～10 秒；小目标、远距离、遮挡、夜间低照度效果下降；不做人脸身份识别 |
| **响应时延** | 事件发生到钉钉收到通知：开启二次确认时 ≤ 20 秒，关闭时 ≤ 12 秒；语音问答首字播报 ≤ 3 秒 |
| **容量** | 单台 4×3090 服务器支持的摄像头路数需压测（与检查间隔、职责数量相关），一期目标 ≥ 4 路 |
| **可用性** | 服务异常自动重启；摄像头离线、模型服务异常、通知发送失败要在岗位卡和钉钉上提示 |
| **数据安全** | 私有化部署，画面和记录不出客户网络；应用凭证加密或权限 600 保存；截图按保留期自动清理 |
| **审计** | 职责增删改、告警处理都有操作记录（谁、何时、改了什么） |
| **易用性** | 业务人员不看文档也能完成“添加职责 → 试一下 → 保存”；所有文案用业务语言，不出现“规则 ID”“VLM”等术语 |

## 7. 版本规划

| 版本 | 范围 | 验收标准 |
|---|---|---|
| **一期**（单岗位，可演示、可试点） | 岗位卡首屏；岗位信息；长期职责（盯守类、汇报类）+ 临时任务；行业模板 1 个；一句话添加；试一下；每条职责独立的通知对象、生效时间、级别；二次确认；告警记录与处理状态（网页上处理）；语音复述确认、“你负责什么” | 新客户 30 分钟内完成开通；试点一周内模板职责准确率 ≥ 85%；值班员能说出系统在负责什么 |
| **二期**（好用、可信） | 试运行模式；参考图与误报反馈；巡检类职责；持续时长条件；钉钉卡片按钮处理；超时升级；统计报表；账号角色 | 误报率较一期下降一半；告警处理率 ≥ 90% |
| **三期**（规模化） | 多路摄像头（总览 + 岗位，职责批量下发）；检测区域框选；自定义模板；企业微信、短信、声光报警器；审计日志导出 | 单客户 ≥ 10 路稳定运行 |
