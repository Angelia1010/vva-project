# AI 值守员 架构说明

产品需求见 [PRD-AI值守员.md](PRD-AI值守员.md)。本文说明后端怎么分层、一次告警怎么流转、后台观察和指令问答怎么同时工作。

## 1. 分层

```
┌──────────────────────────────── 入口层 ────────────────────────────────┐
│  网页值守台（HTTP + WebSocket）   语音（麦克风 / 现场音箱）   钉钉   飞书    │
│  web/                     voice/ audio/          channels/dingtalk  channels/feishu │
└──────────────────────────────────┬───────────────────────────────────┘
┌─────────────────────────────── 编排层 ─────────────────────────────────┐
│  app.py：组装各模块，管理会话（网页、每个钉钉群、每个飞书群各一个）、打断   │
│  core/bus 事件总线：模块之间只通过事件通信，值守台通过 WebSocket 订阅        │
└──────────────────────────────────┬───────────────────────────────────┘
┌──────────────────────────────── 业务层 ────────────────────────────────┐
│  station/  岗位信息                                                  │
│  duties/   职责：清单、引擎（生效时间 / 持续 / 冷却）、复核、定时执行、    │
│            一句话解析、行业模板、智能体工具                             │
│  alerts/   告警：记录、截图、处理状态与经过、统计                        │
│  notify/   通知路由：按职责发到钉钉群 / 飞书群 / 值守台 / 现场播报        │
└──────────────────────────────────┬───────────────────────────────────┘
┌──────────────────────────────── 能力层 ────────────────────────────────┐
│  perception/  后台观察、看图、定位放大      agent/      主智能体            │
│  skills/      技能（目标、参考图、热词）    knowledge/  知识库子智能体       │
│  memory/      长期记忆（时间线、关键帧）    video/      视频源与帧缓存       │
└──────────────────────────────────┬───────────────────────────────────┘
┌──────────────────────────── 模型服务层 ─────────────────────────────────┐
│  GPU0+1 Qwen3.6-35B-A3B（大脑 + 看图）  GPU2 Qwen3-ASR  GPU3 Qwen3-TTS   │
└──────────────────────────────────────────────────────────────────────┘
```

依赖只向下：入口层不懂业务，业务层不直接调模型，能力层不关心告警发给谁。

| 存储 | 内容 |
|---|---|
| `data/ops.db` | 岗位（station）、职责（duties、duty_changes）、告警（alerts、alert_events） |
| `data/alerts/<日期>/` | 告警截图，按 `duties.alert_image_days` 清理 |
| `data/memory/` | 长期记忆：画面记录、时段摘要、备忘、关键帧 |
| `skills/`、`data/knowledge/`、`data/channels/` | 技能、知识库、钉钉飞书配置（不变） |

## 2. 概念

- **岗位**：一个摄像头点位。名称、看哪里、场景说明、负责人，写进智能体和后台观察的提示词。
- **职责**（`vva/duties/model.py`）：
  - 盯守 watch：后台观察每次看画面时一并判断，命中后复核、告警、通知。
  - 巡检 inspect：到点看一次，结果记成“记录”，异常时按告警处理。
  - 汇报 report：到点用长期记忆生成报告，发给通知对象。
  - 临时任务：`temporary=True`，值班员用语音或钉钉/飞书下达，默认当天 24:00 到期，通知回下达的地方。
- **通知对象**：`web` 值守台、`voice` 现场播报、`default` 各入口的默认告警群、`dingtalk:<群>`、`feishu:<群>`。
- **告警状态**：待处理 → 处理中 → 已处理 / 误报；试运行命中为“试运行”，巡检正常为“记录”。

## 3. 一次告警的流转

```
后台观察（perception/observer.py，每 5~10 秒）
  │ 只带当前生效的盯守职责（DutyBook.active），以及技能里相关目标的参考图
  │ 模型返回 triggered_rules → observer.on_hit(职责编号, 依据, 时间, 画面)
  ▼
职责引擎（duties/engine.py）
  │ 生效时间内？冷却期外？持续够久（min_duration_s）？同一职责正在处理中则忽略
  ▼
复核（duties/verify.py，职责开了 verify 才走）
  │ 隔 verify_delay 秒取最新画面 → 判断并定位 → 裁剪放大再确认
  │ 带上技能目标的参考图、这条职责标过的误报截图（“不算”的例子）
  │ 不成立：丢弃，这条职责 30 秒内不再判断
  ▼
告警服务（alerts/service.py）
  │ 落库（截图、依据、目标框、规章依据），记“发现：…”；试运行只记录不通知
  ▼
通知路由（notify/router.py）
  │ 发一条 TOPIC_ALERT（带 targets）到事件总线，记“已通知 …”
  ├─▶ 钉钉 / 飞书入口（channels/chat.py）：按 targets 里自己的前缀或 default 取群，发卡片；送达结果回写处理经过
  ├─▶ 应用（app.py）：targets 有 web 时值守台弹提醒，有 voice 时现场播报
  └─▶ 长期记忆：记成一条提醒，用于“今天有几次……”和报告
```

值守台通过 WebSocket 收到 `alert_new`、`alert_update`、`duties_changed` 后刷新岗位卡、告警卡，并在画面上框出目标。

## 4. 后台观察和指令问答同时工作

两条线是同一个进程里的异步任务，共用帧缓存和模型服务（vLLM 合并批处理并发请求），互不等待：

| | 后台观察 | 指令问答 |
|---|---|---|
| 何时运行 | 常驻，每 5~10 秒；画面无变化时跳过 | 有人说话或发消息时 |
| 做什么 | 写时间线、判断职责、交给职责引擎 | 理解指令、调工具、简短回答 |
| 写入 | 时间线、长期记忆、告警 | 临时任务、备忘、会话上下文 |
| 读取 | 职责清单、技能参考图 | 时间线、长期记忆、职责、告警、技能、知识库 |

配合方式：

- 问“刚才发生了什么”“上午 9 点左右”：智能体查后台观察写下的时间线和长期记忆。
- 说“有人吸烟就通知我”：智能体用 `add_task` 加临时任务，后台观察下一轮就会带上它。
- 问“你负责什么”：职责清单摘要已写进系统提示词，可直接回答；需要细节时调 `list_duties`。
- 告警发出后追问“现在还有人吗”：告警已记进对应会话，智能体知道说的是哪件事。

问答优先：每次提问时 `observer.hold()` 让后台观察暂缓两个周期，避免抢模型；有“紧急”级别的职责生效时不让，避免漏报。

## 5. 智能体工具

| 类别 | 工具 | 所在模块 |
|---|---|---|
| 看画面 | look_now、locate、look_back、look_sequence | agent/tools.py |
| 查记录 | search_timeline、search_memory、look_at_time | agent/tools.py、memory/tools.py |
| 备忘 | remember_note、forget_note | memory/tools.py |
| 职责 | list_duties、add_task、remove_task、pause_duty、resume_duty | duties/tools.py |
| 告警 | query_alerts | duties/tools.py |
| 技能 | 技能的目标判断与插件工具 | skills/ |
| 知识 | ask_knowledge | knowledge/ |

钉钉、飞书里非管理员的会话是只读的，看不到也调不了修改类工具（`agent/conversation.py` 的 WRITE_TOOLS）。

## 6. 接口

岗位、职责、告警：`vva/web/duties_api.py`；技能、知识库、钉钉飞书配置：各自的 `*_api.py`。
页面：`/browser` 值守台、`/duties` 职责、`/alerts` 告警中心、`/skills` 技能、`/knowledge` 知识库、`/settings` 设置（含 `/dingtalk`、`/feishu`）。

## 7. 扩展

- 新增通知渠道（企业微信、短信、声光报警器）：在 `vva/channels/` 下加一个入口，订阅 TOPIC_ALERT，按 `targets` 里自己的前缀取目标。职责和告警模块不用改。
- 新增行业模板：在 `vva/duties/templates.py` 的 TEMPLATES 里加一项。
- 多路摄像头：岗位表已按 `station_id` 设计，职责、告警可加岗位字段后按岗位过滤（三期）。
